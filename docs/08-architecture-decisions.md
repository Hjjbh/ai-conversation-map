# 架构决策记录

本文件保存已接受的关键决策。重要变更应新增 ADR，而不是静默改写历史。

## ADR-001：原始会话为唯一事实源

- 状态：接受
- 决策：ChatGPT 持有消息与会话生命周期；插件只保存投影、引用与组织元数据。
- 原因：避免双写冲突、数据漂移和第二套聊天运行时。
- 结果：插件数据可部分重建；插件不能声称拥有或修改原会话事实。

## ADR-002：Question + Answer 聚合为 Turn/Card

- 状态：接受
- 决策：图谱最小可视节点是完整问答轮次，而非每条消息。
- 原因：降低认知负担，并与“从回答继续探索”的用户心智一致。
- 结果：Projection Engine 必须处理多段回答、流式状态和未完成 Turn。

## ADR-003：布局与逻辑图分离

- 状态：接受
- 决策：坐标、尺寸和折叠属于 LayoutMetadata；关系边来自来源事实或明确用户关联。
- 原因：自由拖拽不应改写会话血缘。
- 结果：任何布局 API 都无权修改 sequence/branch edge。

## ADR-004：首版仅支持 ChatGPT

- 状态：接受
- 决策：先完成单一 Site Adapter 的完整闭环，同时保持 Adapter 接口可扩展。
- 原因：平台 DOM、导航与分支能力差异大，过早多平台会削弱可靠性。
- 结果：领域层不得出现 ChatGPT DOM 概念；平台差异留在 Adapter。

## ADR-005：独立扩展页承载地图

- 状态：暂定接受
- 决策：React Flow 主画布运行在独立扩展页；ChatGPT 页面只保留轻量入口与定位高亮。
- 原因：画布需要空间，且独立页面能减少 CSS 冲突与宿主页面升级影响。
- 结果：需要可靠的跨标签页通信和激活逻辑。

## ADR-006：本地优先，LLM 非核心依赖

- 状态：接受
- 决策：Dexie/IndexedDB 保存插件数据；LLM Gateway 默认关闭且核心功能不依赖它。
- 原因：保护隐私、降低成本与故障面。
- 结果：摘要等智能功能必须可选，并接受单独安全评审。

## ADR-007：未确认的分支不得画成真实分支

- 状态：接受
- 决策：只有 ChatGPT 返回可验证目标引用后，才能创建 `branch` 边；派生上下文只能是 `reference`。
- 原因：防止视觉地图制造不存在的会话事实。
- 结果：分支 UX 必须暴露能力等级与失败状态。

## ADR-008：具体分支实现策略

- 状态：待技术探针
- 待决问题：当前 ChatGPT Web 是否提供稳定、合规且可验证的任意 Turn 原生分支路径。
- 决策门槛：阶段 0 完成真实页面验证并记录能力矩阵后更新。
