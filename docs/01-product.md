# 产品定义

## 1. 问题

长对话天然是线性的，但人的探索过程常常是树状的。用户会回到较早的回答追问、比较多个方向，或者需要快速定位某个结论。原聊天页面适合连续交流，却不擅长展示主题结构、分支关系和探索路径。

## 2. 产品目标

在不替代 ChatGPT 的前提下，提供一张可交互的“会话地图”：

- 让用户看到当前会话由哪些 Question/Answer Turn 构成。
- 让用户从任意 Turn 继续探索，并能识别真实分支与视觉关联。
- 让地图与原聊天互相定位，而不是把用户困在插件中。
- 让视觉组织可自由调整，同时不改变真实会话逻辑。

## 3. 核心用户故事

### P0：首版必须完成

1. 当我打开一条 ChatGPT 会话时，可以打开地图并看到按顺序生成的 Turn 卡片。
2. 每张卡片包含问题摘要、回答摘要、状态和来源定位信息。
3. 当原页面新增或更新回答时，地图只更新受影响的 Turn。
4. 点击卡片时，原页面滚动并高亮对应消息；从原页面触发“在地图中查看”时，地图聚焦对应卡片。
5. 拖动卡片只改变视觉位置，不改变父子关系。
6. 从已完成 Turn 发起分支时，插件使用平台实际支持的动作；无法完成真实分支时给出清晰说明。
7. 刷新浏览器后，布局和用户命名仍然存在；原始消息可以重新投影恢复。

### P1：首版后补充

- 跨会话工作区。
- 卡片折叠、子树折叠、标签和搜索。
- 用户选择回答片段后，以片段作为分支上下文。
- LLM 生成标题、摘要和语义检索。
- Claude、Gemini、DeepSeek 等其他 Site Adapter。

## 4. 明确不做

- 不直接托管或替代 ChatGPT 对话。
- 不在首版实现多账号、云同步或协作编辑。
- 不把画布连线当作真实会话分支。
- 不绕过平台权限、登录、限流或付费规则。
- 不默认把聊天内容发送给第三方模型。
- 不承诺在 ChatGPT 未公开稳定接口的情况下实现永久稳定的 DOM 自动化。

## 5. 默认交互形态

首版采用“独立扩展页作为完整地图 + ChatGPT 页面轻量入口”的组合：

- 独立扩展页承载 React Flow 画布，避免网页空间与样式冲突。
- Content Script 负责读取、监听和定位原聊天。
- 页面内只注入最小入口与短暂高亮，不注入完整画布。

该选择优先保证地图可用空间、可测试性与页面升级后的隔离性。

## 6. 成功指标

- 支持的测试会话中，Turn 投影准确率达到 95% 以上。
- 从卡片定位到原消息的成功率达到 95% 以上。
- 新消息稳定后 1 秒内反映到地图（普通长度回答）。
- 拖动布局后刷新，位置恢复成功率为 100%。
- Adapter 解析失败时不写入错误投影，并能给出可诊断状态。
