# 存储、隐私与安全

## 1. 默认策略

首版为本地优先。除 ChatGPT 页面本身外，插件不把聊天内容发送到任何服务器。LLM Gateway 默认关闭，开启前需要用户选择 Provider、查看发送范围并明确确认。

## 2. IndexedDB 逻辑集合

后续 Dexie schema 至少覆盖：

- `conversations`：来源会话引用与采集状态。
- `sourceMessages`：可重建的标准化消息缓存。
- `turns`：可重建的 Turn 投影。
- `edges`：逻辑边与边来源。
- `layouts`：卡片坐标、尺寸、折叠和视口。
- `annotations`：用户标题、标签与备注。
- `branchOperations`：分支意图、结果和幂等状态。
- `adapterDiagnostics`：不含完整正文的诊断摘要。
- `settings`：隐私、显示、Provider 和功能开关。

具体表结构在代码阶段以 schema 版本 1 落地，并同时提供迁移测试。

## 3. 数据分级

| 级别 | 示例 | 默认处理 |
|---|---|---|
| 敏感内容 | 问题、回答、选中文本 | 仅本地；日志禁写；导出需确认 |
| 来源标识 | 会话 ID、消息 ID、URL | 本地保存；展示时最小化 |
| 用户元数据 | 标签、布局、备注 | 本地持久化 |
| 诊断数据 | 策略版本、计数、错误码 | 可保存；不得含正文与令牌 |
| 密钥 | 第三方 LLM API key | 不进入普通 IndexedDB；代码阶段选择安全存储策略 |

## 4. 权限最小化

计划仅申请首版实际需要的浏览器权限与 ChatGPT host 权限。权限清单必须在脚手架阶段逐项写明用途；没有用例的权限不申请。访问其他站点需要未来 Adapter 独立增加权限并向用户解释。

## 5. 内容安全

- ChatGPT 消息视为不可信输入。
- Markdown/HTML 渲染必须经过清理与 URL scheme 白名单。
- 禁止执行消息中的脚本、事件处理器或内联插件协议。
- 外部图片、链接和附件遵循浏览器安全策略，不静默下载。
- 页面与扩展通信校验来源、消息类型和版本。
- 不在日志、错误上报或剪贴板中隐式暴露聊天正文。

## 6. 删除与导出

设置页需要分别提供：

- 清除可重建缓存：保留布局与用户注释。
- 清除某一会话的地图数据：不影响 ChatGPT 原会话。
- 清除全部本地数据：明确列出将删除的插件数据。
- 导出工作区：默认包含图谱与元数据；是否包含正文由用户选择。

删除操作应可预览范围。任何插件内删除都不得触发 ChatGPT 原会话删除。

## 7. LLM Gateway 隐私门槛

开启任何远程 LLM 功能前，必须满足：

1. 核心地图功能在关闭 LLM 时完整可用。
2. 用户能看到将发送的是全文、路径、单卡片还是选中文本。
3. Provider、模型、保留策略和费用责任清晰。
4. 请求经过统一 Gateway，UI 与领域层不直接调用 Provider。
5. 密钥与响应日志策略通过单独安全评审。
