# 开发路线与验收

## 1. 实施原则

每个阶段先完成可验证的薄切片，再扩大功能。DOM 解析、投影、图谱和存储分别测试，避免把问题全部留给浏览器手工调试。

## 2. 阶段计划

### 阶段 0：技术探针

目标：验证当前 ChatGPT Web 的消息识别、会话标识、定位和真实分支路径。

产物：脱敏 DOM fixture、能力矩阵、选择器策略说明、真实分支 ADR。

退出条件：能稳定读取至少三类会话样本；分支能力有明确 A-E 降级结论。

### 阶段 1：可启动脚手架

目标：建立 WXT + React + TypeScript 工程与测试基线。

计划产物：WXT 配置、扩展入口、类型检查、单元测试、格式与构建命令、开发说明。

退出条件：开发模式可启动；扩展可加载；空地图页与 Content Script 可通信；构建和测试通过。

### 阶段 2：只读投影闭环

目标：从当前 ChatGPT 会话读取消息并显示 Turn/Card。

退出条件：Question+Answer 配对、流式更新、刷新后重建、失败诊断均通过验收样本。

### 阶段 3：布局与持久化

目标：实现 React Flow 画布、拖拽、缩放、折叠和 Dexie 持久化。

退出条件：布局变化不影响逻辑边；清缓存后投影可恢复；用户元数据不丢失。

### 阶段 4：双向定位

目标：地图与 ChatGPT 页面互相定位。

退出条件：标签页已打开/未打开、页面重载、长会话、定位失败等场景均有确定行为。

### 阶段 5：分支闭环

目标：按技术探针结论实现最高可用等级的分支，并完整表达降级。

退出条件：只有平台确认后才产生真实 branch edge；重复点击幂等；失败不产生幽灵节点。

### 阶段 6：质量与发布准备

目标：权限审计、性能测试、Adapter 回归 fixture、数据迁移与用户文档。

退出条件：构建产物可安装；无高风险权限或已解释；核心回归套件通过。

### 阶段 7：可选智能能力

目标：在显式授权下接入 LLM Gateway，用于摘要、标题或语义检索。

前置条件：不影响离线核心功能；隐私与费用说明完成。

## 3. 测试金字塔

### 单元测试

- 消息到 Turn 的配对与状态机。
- 图不变量、路径和子树查询。
- Branch Context 构造与截断。
- 稳定键、幂等合并和 schema 迁移。

### Fixture 测试

- 不同 ChatGPT 页面结构的脱敏 HTML fixture。
- 流式、重试、编辑、多段回答、附件、代码块和缺失节点。
- 选择器策略失败时的诊断结果。

### 集成测试

- Content Script 与 Background/扩展页通信。
- IndexedDB 写入、升级、清除与恢复。
- 地图定位请求与 Adapter 响应。

### 端到端测试

- 加载扩展并打开测试页面。
- 投影、流式更新、布局恢复和双向定位。
- 分支成功、用户取消、超时和失败恢复。

## 4. MVP 验收清单

- [ ] 仅在声明的 ChatGPT 页面运行。
- [ ] 同一快照重复处理不会生成重复 Turn。
- [ ] 一个 Question 与其 Answer 聚合为一张卡片。
- [ ] 流式回答只更新活动卡片。
- [ ] 卡片移动不会修改逻辑父子关系。
- [ ] 刷新后布局与用户注释恢复。
- [ ] 地图可定位原消息，原消息可定位地图卡片。
- [ ] 分支失败时不生成真实 branch edge。
- [ ] 清除插件缓存不影响 ChatGPT 原会话。
- [ ] 日志和诊断不含完整聊天正文或认证信息。
- [ ] 类型检查、单元测试与生产构建全部通过。

## 5. 进入代码阶段的第一批任务

1. 锁定 Node、包管理器和依赖版本。
2. 创建 WXT React TypeScript 最小工程。
3. 定义核心领域类型与模块边界。
4. 先实现纯函数 Projection Engine 与测试。
5. 实现内存 Graph，再接 Dexie repository。
6. 建立 ChatGPT Adapter fixture harness，最后接真实 Content Script。

该顺序确保核心逻辑可以脱离 DOM 测试，并让 Site Adapter 的变化局限在平台边界内。
