# T0-01 ChatGPT 页面与消息结构探针计划

## 1. 文档状态与目标

- 阶段：阶段 0 技术探针。
- 任务：T0-01“当前 ChatGPT 页面与消息结构盘点”。
- 主责：ADP；复核：QSR。
- 当前状态：计划就绪；已收到 S1-R01/R02/R03 三次专用合成会话脱敏结构观察，尚未采集原始 DOM 或形成脱敏 DOM fixture。
- 目标：在后续另行获批的只读探针中，验证 ChatGPT Web 会话容器、消息角色、逻辑顺序、回答状态及可定位结构，并形成最小化、可复测的脱敏 fixture。

本文只定义样本、步骤、证据和验收门槛，不代表真实页面结构、DOM 属性或自动化稳定性已经得到验证。

## 2. 前置门禁

只有下列条件全部满足后，才能从“准备”进入真实页面只读采集：

1. T0-05 经 TL 复核并由 PO 放行。
2. PO 书面批准样本范围、页面表面、账号类型及允许的只读动作。
3. 使用专门构造且可丢弃的非敏感测试会话；不得使用私人、业务或历史真实会话。
4. QSR 确认脱敏步骤、敏感模式扫描规则和人工复核人。
5. 采集工具与保存目录经过检查，保证不会保存 Cookie、令牌、请求头、网络响应、账户区域或完整页面。
6. 每次采集均具有唯一证据编号、批准引用及停止条件。

任一条件缺失时，仅允许完善文档或合成样本，不得访问真实账号页面。

## 3. 三类脱敏样本定义

三类样本均使用合成内容，正文采用可公开的占位文本；会话 ID、消息 ID、URL 参数使用一致假值或加盐不可逆映射。一个实际样本可包含多个子场景，但不得以同一 DOM 副本重复计作不同类别。

| 样本 ID | 样本类别 | 最小构成 | 主要验证点 | 排除项 |
|---|---|---|---|---|
| S1 | 基础已完成线性会话 | 至少 3 个完整 Question + Answer Turn；纯文本；无附件 | 会话容器、用户/助手角色、消息顺序、Turn 配对、完成状态、基础定位句柄 | 不含私人内容；不以单轮会话替代 |
| S2 | 长会话与富结构 | 至少 20 个完整 Turn；包含列表、代码块、表格或多段回答中的至少 3 种；可包含一个仅保留类型与“附件存在”标记的合成附件 | 长页面或延迟渲染、嵌套结构、非正文控件排除、富内容不破坏角色/顺序识别、定位句柄覆盖率 | 不保存附件二进制、真实附件名、外链正文或账户信息 |
| S3 | 动态与变体状态 | 至少覆盖流式中、已完成、中断/错误中的 3 种状态；编辑、重试或多回答只使用预先准备的可丢弃结果或另行授权的状态变更步骤 | 活动回答识别、局部变化范围、状态转换、重复/替代回答诊断、容器替换后的重绑候选 | 当前授权下不得为制造样本而发送、编辑、重试或重新生成 |

### S3 的授权拆分

- 当前只可定义状态和读取已有的合成/脱敏材料。
- 若后续需在页面上制造流式、编辑、重试或错误状态，必须拆为独立状态变更任务，说明影响、取消和清理方案并逐项取得 PO 授权。
- 未获授权时，缺少的 S3 子场景必须记录为“未采集”，不得用推测 DOM 补齐。

## 4. T0-01 执行步骤

### P0：公开与本地资料基线

1. 记录本地架构、Adapter、隐私和任务卡约束。
2. 只查阅公开官方资料，区分产品行为说明和网页实现细节。
3. 建立待验证假设清单；公开资料未声明的 DOM 属性、选择器和时序一律标记“未验证”。

### P1：样本设计与授权

1. 为 S1–S3 编写无敏感信息的测试内容清单。
2. 为每类样本指定预期 Turn 数、结构特征和状态标签。
3. 由 QSR 审核脱敏方案，TL 核对任务边界，PO 批准真实页面只读范围。

### P2：受控只读观察（尚未授权）

1. 用户手动打开明确纳入探针的专用测试会话。
2. 记录页面类型、浏览器版本、语言、视口和测试时间，不记录账户身份。
3. 只在会话区域识别容器、消息候选、角色、顺序、状态和稳定属性。
4. 对每个关键目标按“语义/稳定数据属性 → 结构/角色特征 → 易变 class”记录候选策略；不得预设某个选择器稳定。
5. 只截取复现结构差异所需的最小 DOM 子树，不采集脚本、样式、隐藏账户区域、网络数据或无关页面。
6. 每类样本至少进行 3 次独立解析记录；刷新或容器替换仅在获批的只读动作范围内执行。

### P3：脱敏与 fixture 形成（尚未授权）

1. 删除脚本、样式、事件属性、网络端点、账户区域和无关节点。
2. 将正文、标题、附件名、ID 和 URL 参数替换为确定性占位符，同时保持同一 fixture 内的引用关系。
3. 只保留角色、顺序、状态、必要属性名、结构层级和可复现的合成内容形态。
4. 执行敏感模式扫描并由非作者人工复核；无法可靠脱敏的材料不落盘。
5. 为 fixture 生成内容哈希，并登记来源证据编号和脱敏版本；不得记录原始标识到映射表。

### P4：分析与复核

1. 统计容器识别、角色分类、顺序恢复、回答状态、Turn 配对、未识别节点和定位句柄覆盖率。
2. 对主策略、回退策略和失败策略分别给出命中证据。
3. 低置信度时只输出诊断，不覆盖上一次稳定来源映射。
4. QSR 对 fixture 脱敏、失败降级和指标计算进行独立复核。

## 6. 指标与验收阈值

### 6.1 计算口径

- 角色准确率 = 角色正确的预期消息数 ÷ 预期消息总数。
- 顺序准确率 = 位于正确逻辑位置的预期消息数 ÷ 预期消息总数。
- 回答状态准确率 = 状态判断正确的预期回答数 ÷ 预期回答总数。
- Turn 投影准确率 = 正确聚合的预期 Turn 数 ÷ 预期 Turn 总数。
- 定位句柄覆盖率 = 至少具有一个可重建定位候选的预期消息数 ÷ 预期消息总数。
- 未识别节点必须区分“目标消息节点”和“已确认无关节点”，不得通过忽略失败节点抬高指标。

### 6.2 T0-01 放行阈值

1. S1、S2、S3 三类均有独立脱敏 fixture 和完整证据记录；缺少任何一类则 T0-01 不通过。
2. 每类样本的会话容器识别成功率为 100%，消息角色准确率、顺序准确率和回答状态准确率均为 100%。
3. 三类样本合计 Turn 投影准确率不低于 95%，且任何单类不得低于 90%。
4. 三类样本合计定位句柄覆盖率不低于 95%，且每个无法定位的目标节点均有明确错误码和回退结论。
5. 同一脱敏 fixture 连续解析 3 次，消息数量、角色、顺序和稳定来源候选结果一致，不产生重复 Turn。
6. 目标消息未识别或误识别不得静默发生；所有失败均进入结构化诊断。解析置信度为 low 时必须保留上次有效地图并禁止覆盖稳定映射。
7. 每个关键目标至少记录一种主策略及一种失败/回退行为；仅依赖易变 class 名不能通过。
8. fixture、日志与证据通过自动敏感模式扫描和 QSR 人工复核，敏感信息命中数必须为 0。

这些阈值用于阶段 0 的受控样本验收，不构成对未来所有 ChatGPT Web 版本的永久稳定性承诺。

## 7. 禁止范围与熔断

### 7.1 明确禁止

- 访问真实私人、业务或未明确纳入探针的账号会话。
- 保存完整页面、完整正文、真实 ID、完整 URL、附件内容、Cookie、令牌、请求头或网络响应。
- 调用未授权私有接口，绕过登录、限流、付费或站点安全机制。
- 为制造样本而发送消息、填充输入框、编辑、重试、重新生成、分支、删除、分享或修改账户状态。
- 读取其他标签页、浏览历史、下载、书签、剪贴板或账户资料。
- 让 Adapter 直接写图谱/数据库，或在低置信度下覆盖稳定映射。
- 把 DOM 节点引用持久化，或把公开产品说明当成 DOM 稳定性证据。

### 7.2 立即停止条件

发现未授权数据、采集范围越界、需要状态变更、无法可靠脱敏、目标节点身份不明、低置信度可能导致错绑，或证据链缺少批准引用时，立即停止该样本；只保留脱敏的错误码和抽象复现条件，并提交 QSR/TL 重新放行。

## 8. 当前结论与未完成项

- 三类样本及其验证口径已经定义。
- S1-R01 脱敏结构观察识别 6/6 条消息，用户/助手角色与逻辑顺序符合 3 个 Turn 的预期；列表和表格结构信号被保留。
- S1-R01 的 3 条 Assistant 消息状态均为 `unconfirmed`，因此本次观察不能通过回答状态验收，也不能由 `streamingSignalCount: 0` 推断回答已完成。
- 每条消息均报告存在 `data-message-id` 和 `data-testid` 候选，但没有保存属性值；身份稳定性和跨生命周期可用性仍未验证。
- 当前材料只是脱敏结构观察 JSON，不是原始 DOM 或脱敏 DOM fixture。R01/R02/R03 除 `capturedAt` 外完整 JSON 值树一致，S1 静态结构重复性达到当前样本要求；回答状态 0/9，因此 S1 整体仍未通过。S2/S3 尚未运行。
