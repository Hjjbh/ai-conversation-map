# T0-01 只读脱敏采集工具

## 1. 状态与用途

- 工具文件：`tools/stage-0/chatgpt-readonly-probe.js`
- 当前候选版本：`0.2.0`
- 适用任务：T0-01 的 P2“受控只读观察”准备
- 当前状态：`0.1.0` 已通过 QSR 复核并完成 S1 三次运行；`0.2.0` 已通过 QSR 技术复核，但真实页面运行仍需 PO/用户明确授权
- 适用页面：仅限 PO 已批准、由 S1/S2/S3 脚本生成的专用非敏感、可丢弃测试会话

该工具是阶段 0 的隔离证据工具，不是浏览器插件正式源码，也不代表当前选择器已经通过真实页面验证。

## 2. 安全边界

工具具有以下硬性限制：

1. 只允许在 HTTPS 的 `chatgpt.com` 或 `www.chatgpt.com` 会话路径运行；非 HTTPS、其他主机、首页和其他路径均在读取 DOM 前熔断。
2. 默认不自动执行。加载后必须由操作人明确调用 `AICMReadonlyProbe.run()`。
3. 不使用网络、IndexedDB、Local Storage、Session Storage、Cookie、剪贴板或下载能力。
4. 不改变 ChatGPT 用户、会话或可见页面状态：不点击、滚动、聚焦、高亮、填写、发送、编辑、停止、重试、重新生成或创建分支。
5. 不输出聊天正文、原始 ID、属性值、URL、URL 参数、DOM 片段、class 名、账户信息或附件名。
6. 只输出消息序号、用户/助手角色、正文长度区间、富结构元素计数、部分属性是否存在、固定状态提示和固定证据类别。
7. “完成”状态没有可靠信号时输出 `unconfirmed`，不得由“未发现流式信号”推断为已完成。
8. 若页面有多个 `main`、消息容器越界、同一容器角色冲突或候选超过 500 条，立即返回结构化阻断结果。
9. 工具会临时创建不可枚举的 `AICMReadonlyProbe` 页面全局对象；已有同名属性时拒绝覆盖，操作结束后可显式清理。
10. 浏览器公开对象只包含 `version`、`run()` 和 `dispose()`；内部解析函数和测试注入点不会暴露到页面。

## 3. 输出结构

| 字段 | 含义 |
|---|---|
| `schemaVersion` | 脱敏报告结构版本 |
| `probeVersion` | 工具版本 |
| `capturedAt` | 本次内存观察时间 |
| `status` | `observed` 或 `blocked` |
| `errorCodes` | 结构化停止原因 |
| `page` | 固定表面、主机允许状态和粗粒度路径类型 |
| `summary` | 消息、角色、流式/完成/冲突候选信号数量 |
| `messages` | 每条候选消息的脱敏结构摘要 |
| `limitations` | 本次结果不能支持的结论 |

`messages` 不含任何原文或源属性值。`textLengthBucket` 只保留 `empty`、`1-40`、`41-200`、`201-1000`、`1000+` 五个区间。schema 2 的 `stateEvidence` 只保留 `ariaBusyTrue` 布尔值和固定的完成操作类别，不输出选择器命中的属性值。

## 4. 受控运行步骤

### 4.1 运行前

1. 确认页面是按照 S1、S2 或 S3 脚本新建的专用测试会话，不是私人、业务或历史会话。
2. 关闭含无关敏感信息的其他开发者工具输出，并确认当前地址主机为 `chatgpt.com`。
3. 记录待使用的证据编号，例如 `T0-01-S1-R01`；编号中不得包含真实会话 ID。
4. 首次真实页面运行前，由 QSR 确认本文件、工具版本和本地测试结果。

### 4.2 手动执行

1. 在目标测试会话打开浏览器开发者工具的 Console。
2. 将 `tools/stage-0/chatgpt-readonly-probe.js` 的完整内容作为一次性脚本加载。
3. 手动执行：

   ```js
   AICMReadonlyProbe.run()
   ```

4. 在 Console 中展开结果，先人工确认它不含正文、原始标识、完整 URL、账户信息或其他敏感值。
5. 核对 `summary.messageCount` 与测试脚本的预期消息数。数量不符时停止，不手工修改结果冒充成功。
6. 需要提交项目分析时，只传递这份已预览的脱敏对象；不要提交 Console 历史、页面截图、原始 DOM 或完整页面保存文件。
7. 完成观察后手动执行 `AICMReadonlyProbe.dispose()`；返回 `true` 表示临时全局对象已清理。

工具不调用浏览器的 `copy()` 或任何剪贴板 API。若操作人决定转交结果，必须先完成第 4 步预览，再以明确的人工动作复制单个脱敏对象。`capturedAt` 是输出中唯一的精确时间字段，转交前同样需要人工确认。

### 4.3 重复观察

- S1、S2、S3 每个可用场景按任务计划至少独立运行 3 次。
- 每次重新调用 `run()`，不复用或改写前一次返回对象。
- 流式场景只观察自然存在或由用户在授权窗口内手动触发的状态；工具不会制造状态。
- 本工具当前不滚动页面。长会话因虚拟化而缺失节点时记录数量差异，不扩大动作范围。

## 5. 停止与失败处理

出现下列任一情况立即停止该样本：

- 当前页面不是明确批准的合成测试会话。
- 结果出现正文、真实标识、完整 URL、账户资料或未定义字段。
- 工具要求放宽主机、读取网络、持久化、下载、剪贴板自动写入或页面状态变更才能继续。
- 消息数量、角色顺序或容器范围与测试脚本明显不符。
- 页面结构不能在不读取无关区域的前提下识别。

停止后只记录脱敏错误码、工具版本和抽象限制。任何选择器调整都应在合成测试中验证并重新接受 QSR 复核后再运行。

## 6. 本地验证

在项目根目录、已安装 Node.js 的环境中运行：

```powershell
node --test tools/stage-0/chatgpt-readonly-probe.test.js
```

测试覆盖：协议/主机/路径前置熔断，缺失或歧义根区域，空消息、角色冲突、候选超限和容器越界，正文/标识/URL/属性值/账户诱饵不出现在严格白名单输出，同角色重复容器去重，完成正向信号、流式/完成冲突、反馈信号不足降级、公开 API 白名单、全局名称冲突与清理，以及源码不引用外部 I/O 或页面交互 API。测试只使用内存中的合成 DOM 替身，不访问 ChatGPT 或其他网络。

## 7. 当前限制与下一门禁

- 选择器和容器回退仅是待验证假设，不是稳定性承诺。
- 工具不会读取或输出真实来源 ID，因此当前结果只能支持结构盘点，不能单独完成 T0-02 身份稳定性结论。
- 工具不执行滚动或高亮，不能单独完成 T0-03 双向定位。
- 每个新版本首次真实页面运行前必须取得 QSR 对源码、schema 和文件哈希的独立放行。
- 只有收到 S1/S2/S3 的脱敏输出并通过敏感信息扫描与人工复核后，才能创建正式 fixture 和证据记录。
