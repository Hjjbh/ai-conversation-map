## 3. TL 交叉评审结果

ADP、GDE、UIE 已分别复核 T0-05。TL 根据反馈完成以下统一：

1. 获批专用测试会话中的正文只可在当前操作内存中瞬时处理；未经授权读取或任何普通日志/导出/外发立即熔断。
2. 真实附件名不进入 fixture、日志或持久证据。
3. 阶段 0 项目证据不保存原始来源 ID 或完整 URL 参数。
4. 内容指纹属于敏感派生数据，禁止无盐正文直接哈希和进入普通日志。
5. 身份迁移候选使用字段白名单，具备过期/清除机制，确认前不重挂元数据。
6. 用户明确点击“打开原会话”可作为单次开页授权；批量、自动重试或后台开页仍需独立批准。
7. 消息来源校验必须依赖浏览器运行时 sender、目标入口、tab/frame 上下文和 payload schema，不能只信任消息自报字段。

QSR 最终结论为“有条件通过，可提交 PO 审批”。

## 4. 来源标识策略取舍

T0-05 的“阶段 0 证据不保存原始来源标识”与产品未来“重启后仍可从地图打开原会话”需要区分作用域。

### 推荐方案

- **阶段 0 项目文件与共享证据**：只使用一致假值或不可逆映射，永不保存真实会话 ID、消息 ID、完整 URL 参数或私人正文。
- **未来正式插件的本地 IndexedDB**：为了持久化双向定位，可在用户启用功能后保存最小必要的真实会话 ID、消息 ID和不含查询参数的规范 URL；这些字段按敏感来源标识处理，仅保存在本机，不进入普通日志、遥测或默认导出，并提供按会话/全部清除。
- **远程外发**：保持禁止；任何云同步、遥测或 LLM 使用另行 ADR、QSR/TL 评审和 PO 批准。

该方案保留核心定位能力，同时避免把阶段 0 的真实标识写进项目文档或测试 fixture。

### 更严格备选

正式插件也不保存真实来源标识。隐私面更小，但浏览器重启后可能无法可靠从地图返回原会话，用户元数据重挂接能力也会下降。
