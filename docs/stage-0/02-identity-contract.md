# T0-02 会话与消息身份契约

## 1. 文档状态与范围

- 阶段：阶段 0 技术探针。
- 任务：T0-02“会话/消息稳定身份验证”的契约准备。
- 主责：ADP；复核：GDE + QSR。
- 输入：T0-01 的脱敏 fixture、结构报告与选择器策略。
- 输出：身份能力矩阵、稳定性结论、降级策略和迁移候选规则。
- 本文只定义跨模块可观察的数据语义，不规定 TypeScript、Dexie 或 DOM 的具体实现。
- 本文不代表真实 ChatGPT 页面结构已经验证，也不授权读取真实账号会话、保存真实正文或执行编辑、重试、分支、发送等状态变更动作。

## 2. 契约目标

身份层必须支持以下结果：

1. 同一会话的重复快照可幂等合并。
2. 流式回答的内容修订更新原消息和原 Turn，不创建重复节点。
3. 页面刷新、虚拟列表重建或 DOM 节点替换不改变已确认身份。
4. 编辑、重试和回答版本切换能够表达“同一逻辑位置的新修订”或“新的来源版本”，不得用内容相似替代平台事实。
5. 身份证据不足时输出低置信度或迁移候选，不静默覆盖稳定映射或错绑用户元数据。
6. 领域层只接收安全、可序列化的快照；DOM 节点、认证信息和未经清理的页面对象不得跨越 Adapter 边界。

## 3. 通用字段约定

以下约定适用于本文三个对象：

| 概念 | 契约 |
|---|---|
| 键命名空间 | 所有来源键均绑定 `platform` 与 Adapter 身份策略版本，禁止假定不同平台或不同策略产生的裸 ID 可直接比较。 |
| 空值 | “页面未提供”“尚未观察到”和“解析失败”必须可区分；不得用空字符串混为一种状态。 |
| 时间 | 页面能提供可信时间时保存标准化时间及来源；否则只保存 `observedAt`，不得把采集时间伪装成消息创建时间。 |
| 顺序 | 顺序字段表达 Adapter 在该来源会话内观察到的逻辑位置，不以屏幕坐标或当前 DOM 插入次序为事实。 |
| 内容 | 正文是可重建投影数据，不参与日志；内容指纹仅作降级身份佐证，不能单独证明同一消息。 |
| 版本 | `adapterVersion` 表达采集实现版本；`identityStrategyVersion` 表达键推导规则版本；二者变化都必须可诊断。 |
| 证据 | 每个来源键附带身份层级、证据摘要与置信度，不把“已生成键”误作“已获得稳定身份”。 |
| 可序列化 | 对象不得包含 DOM 节点、函数、页面对象、事件对象、循环引用、Cookie、令牌或请求头。 |

## 4. `ConversationSnapshot` 字段契约

`ConversationSnapshot` 是 Adapter 在一次受控观察中输出的原子快照。它描述“本次看到了什么”，不是数据库记录，也不承诺页面内容完整。

| 字段概念 | 必需性 | 语义与约束 |
|---|---:|---|
| `snapshotKey` | 必需 | 本次采集实例的唯一诊断键；不得作为会话或消息的长期身份。 |
| `schemaVersion` | 必需 | 快照文档协议版本，用于判别兼容性。未知主版本必须拒绝合并并返回协议错误。 |
| `platform` | 必需 | 首版固定为 `chatgpt`。 |
| `adapterVersion` | 必需 | 生成快照的 Adapter 版本。 |
| `identityStrategyVersion` | 必需 | 会话键、消息键及证据判定规则版本。 |
| `observedAt` | 必需 | 本次成功观察完成时间，不代表平台内容创建时间。 |
| `observationScope` | 必需 | 说明是完整可见会话、受影响范围、单条活动消息或定位补采；增量快照不得伪装为全量快照。 |
| `completeness` | 必需 | `complete`、`partial`、`unknown` 之一，并附缺失原因；只有证据充分时才可声明 `complete`。 |
| `conversation` | 必需 | 一个 `SourceConversation`。若会话身份无法形成，整份快照进入诊断，不下发可合并会话。 |
| `messages` | 必需 | 按逻辑顺序排列的 `SourceMessage` 集合；可为空，但必须与 `completeness` 和诊断一致。 |
| `activeMessageKey` | 可选 | 当前流式或受影响消息的来源键；不存在或无法确认时明确为空。 |
| `captureReason` | 必需 | 首次加载、刷新、页面导航、流式变化、编辑/重试后重扫、定位补采或人工重新同步。 |
| `diagnostics` | 必需 | 仅含策略编号、计数、错误码、置信度和脱敏关联键；不得包含完整正文、原始 DOM、令牌或完整 URL 参数。 |

快照级约束：

- 同一快照内所有消息必须属于 `conversation.sourceKey`。
- `messages` 中不得出现相同 `sourceMessageKey` 的冲突记录；若页面同时展示多个回答版本，必须以版本字段明确区分。
- `partial` 或 `unknown` 快照不得据此删除此前已保存但本次未观察到的消息。
- 只有经全量范围确认且删除语义另有证据时，缺失消息才可形成删除候选；阶段 0 不把 DOM 缺失直接解释为平台删除。

## 5. `SourceConversation` 字段契约

| 字段概念 | 必需性 | 语义与约束 |
|---|---:|---|
| `sourceKey` | 必需 | Adapter 命名空间内的会话稳定键；不得包含正文。 |
| `platform` | 必需 | 首版固定为 `chatgpt`。 |
| `platformConversationId` | 可选 | 页面明确提供且允许使用的稳定会话 ID；保留原值只限本地来源引用，诊断与报告需最小化。 |
| `canonicalUrl` | 条件必需 | 可验证的规范会话地址；无法获得时必须提供原因。不得把临时路由或带敏感查询参数的 URL 当作规范地址。 |
| `title` | 可选 | 平台标题的投影，可为空且不参与身份判断。标题变化不得改变 `sourceKey`。 |
| `identityTier` | 必需 | 本文第 7 节定义的身份层级。 |
| `identityEvidence` | 必需 | 使用了哪些稳定字段、哪些字段缺失及冲突情况的脱敏摘要。 |
| `identityConfidence` | 必需 | `high`、`medium`、`low` 或 `unknown`。 |
| `firstObservedAt` | 可选 | 当前工作区首次观察时间；若 Adapter 不掌握则由 Repository 补充，不得伪装为平台创建时间。 |
| `observedAt` | 必需 | 最近一次成功采集时间。 |
| `adapterVersion` | 必需 | 产生当前投影的 Adapter 版本。 |
| `identityStrategyVersion` | 必需 | 当前 `sourceKey` 的身份策略版本。 |
| `capabilitiesRef` | 可选 | 指向同次能力快照的脱敏引用，不把动态能力位混入稳定身份。 |

会话键规则：

- 标题、正文、消息数量、当前选中回答版本、滚动位置和页面标签标题均不得作为会话身份的唯一依据。
- 规范 URL 只有在路径中的会话标识已验证稳定且查询/片段被规范化后，才可作为高层级证据。
- 会话键策略升级时，旧键不得就地覆盖；必须产生旧键到新键的迁移候选并保留来源证据。

## 6. `SourceMessage` 字段契约

| 字段概念 | 必需性 | 语义与约束 |
|---|---:|---|
| `sourceMessageKey` | 必需 | 在 `sourceConversationKey` 内稳定的消息来源键。 |
| `sourceConversationKey` | 必需 | 所属会话键；一条消息只能属于一个来源会话。 |
| `platformMessageId` | 可选 | 页面明确提供且经验证的稳定消息 ID。 |
| `role` | 必需 | 至少区分 `user`、`assistant`、`system`、`tool`、`unknown`；首版投影只按受支持角色聚合。 |
| `logicalIndex` | 必需 | 本次快照中的逻辑顺序；是排序和降级身份佐证，不是跨编辑场景的永久身份。 |
| `content` | 必需 | 安全、可序列化的纯文本或受控结构化块；可暂时为空。不得包含原始 DOM。 |
| `contentFingerprint` | 条件必需 | 仅在需要派生身份、修订比较或相似匹配时提供；采用带策略版本的本地确定性摘要，不进入通用日志。 |
| `contentRevision` | 必需 | 对同一已确认消息身份的单调修订序号。相同内容的重复观察不得增加序号。 |
| `generationState` | 必需 | `pending`、`streaming`、`complete`、`interrupted`、`unresolved` 或可映射的扩展状态。 |
| `answerGroupKey` | 可选 | 平台能识别重试/再生成回答组时，表示这些候选共享的逻辑回答位置。 |
| `answerVersionKey` | 可选 | 区分同一回答组下的平台回答版本；不得仅以可见/隐藏状态区分身份。 |
| `isActiveVersion` | 可选 | 当前页面选择的回答版本；该值变化不得删除其他已确认版本。 |
| `createdAt` | 可选 | 仅在平台提供可信值时填写，并记录时间来源。 |
| `observedAt` | 必需 | 最近成功观察时间。 |
| `locator` | 可选 | 可序列化、可过期的定位句柄及策略版本；不得保存 DOM 引用。定位句柄失效不等同于消息身份失效。 |
| `identityTier` | 必需 | 本文第 7 节定义的身份层级。 |
| `identityEvidence` | 必需 | ID、稳定属性、上下文锚点、角色/顺序/指纹等证据摘要与冲突。 |
| `identityConfidence` | 必需 | `high`、`medium`、`low` 或 `unknown`。 |
| `identityStrategyVersion` | 必需 | 生成当前消息键的策略版本。 |

消息级约束：

- `sourceMessageKey` 相同但角色冲突时必须熔断合并并进入诊断。
- `contentRevision` 只描述同一消息身份下的内容变化，不等同于平台回答版本。
- `logicalIndex` 改变可能源自虚拟列表、漏采或前序编辑，不得单独导致新建或合并消息。
- `locator` 属于导航能力，不得反向定义 `sourceMessageKey`。
- 附件首版只记录类型、来源存在性及合成/脱敏名称；真实附件名只能在获批操作中瞬时处理，不进入持久证据，也不得将二进制内容纳入身份指纹。

## 7. 身份优先级与键策略

身份判定从高到低分三层。每次命中都必须记录策略版本和实际证据，不能只记录最终键。

### Tier 1：平台稳定标识

- 会话：经验证稳定的平台会话 ID，或包含该稳定 ID 的规范化会话路由。
- 消息：经验证稳定且在所属会话内唯一的平台消息 ID。
- 验证要求：至少覆盖重复扫描和页面刷新；适用场景还应覆盖流式完成、回答版本切换及编辑/重试。
- 单次看到类似 ID 的属性不自动获得 Tier 1，必须由 T0-02 能力矩阵证明稳定性与唯一性。

### Tier 2：稳定页面属性组合

- 使用经多个 fixture 和生命周期场景验证的稳定属性组合。
- 属性组合必须具有会话内唯一性，并且不依赖 DOM 节点实例、CSS 类名、屏幕位置或完整正文。
- 任一组成属性发生冲突或失去唯一性时，降为迁移候选，不得继续标记高置信度。

### Tier 3：派生键

- 会话：Adapter 命名空间、规范化路由证据和其他非正文稳定信号的组合。
- 消息：会话键、角色、逻辑位置、邻接锚点和内容指纹的版本化组合。
- 派生键是降级方案。内容指纹、角色加序号或相似文本均不得单独作为高置信度身份。
- 内容指纹属于敏感派生数据，必须采用带策略版本的本地加盐方案，不得使用无盐正文直接哈希，也不得进入普通日志或共享报告。
- 前序消息编辑、插入、漏采或回答版本切换可能导致派生键漂移，因此必须允许输出迁移候选。

键的最低安全要求：

- 键不得直接包含问题、回答、选中文本、标题或附件正文。
- 同一策略和同一输入应生成同一键；策略变更必须提升 `identityStrategyVersion`。
- 碰撞、同键角色冲突、跨会话复用或一对多映射均为阻断性错误。

## 8. 置信度契约

置信度是基于证据的离散结论，不是 UI 美化值，也不得因合并成功自动提升。

| 等级 | 最低含义 | 允许行为 |
|---|---|---|
| `high` | 稳定标识或属性组合已在规定生命周期场景中验证；会话内唯一，且无冲突证据。 | 可自动幂等合并；可按稳定键重挂接元数据。 |
| `medium` | 多项独立证据一致，但缺少一个关键生命周期验证，或只能使用经约束的派生键。 | 可更新可重建投影；不得自动迁移不可重建元数据，需保留候选与旧映射。 |
| `low` | 主要依赖顺序、内容相似或单一弱属性，且编辑、漏采或重试可能造成歧义。 | 仅生成诊断/迁移候选；禁止覆盖稳定映射、删除旧记录或重挂接用户元数据。 |
| `unknown` | 证据缺失、互相冲突、协议不兼容或无法判断唯一性。 | 不进入自动身份合并；请求重新扫描或人工确认。 |

降级规则：

- 稳定证据消失、唯一性失败、角色冲突、策略版本未知或出现一对多候选时，必须降低置信度。
- 新快照的低置信度结论不能覆盖已有高置信度映射；旧地图保留并标记为待重新同步。
- 从低/中提升到高必须有新增证据，并在诊断中记录提升原因。

## 9. 幂等与合并规则

合并顺序为：协议兼容检查 → 会话身份匹配 → 消息身份匹配 → 修订比较 → 投影更新。不得先按内容或坐标修改图谱。

1. 相同 `sourceKey` / `sourceMessageKey`、相同策略版本、相同规范化内容和状态的重复快照是无操作更新，不增加 `contentRevision`，不创建新 Turn 或边。
2. 同一高置信消息键的流式正文发生变化时，更新该消息并单调增加 `contentRevision`；对应活动 Turn 原位更新。
3. 状态从 `streaming` 到 `complete` 且内容不变时，仅更新状态；不得创建新消息。
4. 快照乱序到达时，较旧的观察不得覆盖较新的已确认修订。无法比较修订先后时进入冲突诊断。
5. `partial` 快照中的缺失不得触发删除；重复消息不得因 DOM 节点重建再次插入。
6. 同键不同角色、同一平台 ID 映射多个会话、修订倒退或高置信键碰撞时停止自动合并。
7. 分支边不属于身份合并的推断结果；只有独立、可验证的 `BranchResult` 才能产生真实 `branch`。

## 10. 生命周期场景规则

### 10.1 页面刷新与 DOM 重建

- DOM 节点实例、React 内部实例、CSS 类名和屏幕位置变化不得改变身份。
- Tier 1/2 证据稳定时沿用来源键；定位句柄可以重新生成。
- 仅观察到部分消息时保留未观察到的旧投影，不推断删除。

### 10.2 流式回答

- 首次发现 Assistant 输出时创建或匹配一个活动消息；后续文本增长更新相同 `sourceMessageKey`。
- 内容变化推动 `contentRevision` 单调增加；重复 observer 事件不增加修订。
- 完成、停止、错误、继续生成必须更新状态机，不因状态切换创建重复 Turn。
- 若平台在流式中替换稳定 ID，旧、新标识先形成迁移候选；除非有强证据证明同一消息，否则不静默换键。

### 10.3 用户编辑问题

- 平台保留同一消息 ID 且语义明确为原消息修订时：沿用身份、增加 `contentRevision`，并触发后续路径重新投影候选。
- 平台产生新消息 ID 或新会话路径时：建立新的来源消息，不以文本相似合并到旧消息。
- 只有派生键时：编辑可能造成键漂移，必须结合邻接锚点、角色、逻辑位置与相似度生成候选；置信度不足时保留旧元数据并等待确认。
- 不因编辑自动改写已确认的真实分支血缘。

### 10.4 重试、重新生成与回答版本切换

- 平台提供回答组与版本 ID 时，分别记录 `answerGroupKey` 和 `answerVersionKey`；版本切换只改变活动版本标记。
- 新版本不得覆盖旧版本的来源身份。首版 UI 即使只展示活动版本，投影层也必须避免把版本切换解释为原消息内容修订。
- 平台只展示单一活动版本且无法稳定识别版本时，输出能力限制；不得假定隐藏版本已删除。
- 重试导致新会话路径时按新来源事实处理，不能仅凭相同问题文本合并。

### 10.5 插入、漏采与顺序变化

- `logicalIndex` 不是永久身份。前序插入、虚拟列表补载或漏采恢复后，应重新计算顺序但保持已有稳定键。
- 只有 Tier 3 时，顺序整体漂移必须触发候选匹配；不得批量静默迁移。
- 孤立 Assistant 消息保留为 `unresolved` 诊断对象，不强行配对到最近 Question。

## 11. 元数据重挂接与迁移候选

用户标题、标签、备注、布局、折叠和视口属于不可重建元数据。它们只能依据已确认身份重挂接。

### 11.1 自动重挂接

同时满足下列条件才允许自动执行：

- 旧、新记录属于同一高置信 `SourceConversation`。
- 存在一对一的高置信消息身份映射，或稳定 Turn 来源集合一致。
- 角色、回答版本语义和逻辑关系无冲突。
- 没有其他候选竞争同一旧元数据。

自动重挂接只能改变元数据引用，不得修改元数据内容、逻辑父子关系或已确认边类型。

### 11.2 迁移候选

未达到自动条件时，输出可审计的候选记录，至少包含：

- 旧键、新键及各自身份策略版本。
- 候选关系：一对一、一对多、多对一或无匹配。
- 使用的证据类型与冲突项，不包含正文原文。
- 置信度、产生原因和建议动作。
- 受影响的元数据类别和数量。

`medium` 只允许生成候选并保持旧元数据；`low` / `unknown` 禁止自动重挂接。用户未确认前，旧数据不得删除，新对象不得继承其注释或布局。

### 11.3 熔断条件

发现以下任一情况，停止该范围的自动迁移：

- 同一旧键对应多个同等候选。
- 多个旧键争用同一新键。
- 会话归属、角色或回答版本语义冲突。
- 高置信映射被低置信快照否定。
- 身份策略升级无法解释键变化。
- 元数据重挂接可能改变 sequence/branch 血缘。

处置方式是保留最后一次有效地图、标记待确认、记录脱敏诊断并允许重新扫描。

## 12. ADP 身份能力矩阵要求

ADP 在 T0-01 fixture 可用后，应按每类会话样本分别填写：

| 能力项 | 需要记录的证据 |
|---|---|
| 会话稳定标识 | 属性/路由策略编号、刷新前后是否一致、唯一性、是否含敏感参数。 |
| 消息稳定标识 | 角色覆盖、刷新/流式/版本切换前后是否一致、会话内唯一性。 |
| 回答版本身份 | 是否存在回答组、版本键与活动版本标识，切换时的可观察行为。 |
| 顺序可靠性 | 虚拟列表、懒加载、插入和漏采恢复对逻辑顺序的影响。 |
| 定位句柄 | 是否可序列化、是否跨刷新有效、失效时能否由来源键重建。 |
| 内容修订 | 流式、编辑、停止/继续时能否区分同一消息修订与新来源版本。 |
| 降级结果 | Tier、置信度、缺失证据、冲突、熔断或人工确认条件。 |

任何未通过真实证据验证的项必须标记“未确认”，不能从字段名称、DOM 外观或单一样本推断稳定。

## 13. 验收矩阵

| 编号 | 场景 | 输入/操作（仅限获批脱敏 fixture 或专用样本） | 预期身份结果 | 验收证据 |
|---|---|---|---|---|
| ID-01 | 同一完整快照重复处理 | 连续输入两次相同快照 | 会话、消息和 Turn 数量不变；`contentRevision` 不变 | 合并前后计数与修订对比 |
| ID-02 | 页面刷新 | 比较刷新前后的脱敏结构 | 稳定键保持；DOM 实例/定位句柄可变化 | 键映射及证据摘要 |
| ID-03 | DOM 节点替换 | 等价消息由新节点承载 | 不创建新消息；不保存 DOM 引用 | 序列化检查与合并结果 |
| ID-04 | 流式文本增长 | 同一活动回答多次修订 | 同一消息键；修订单调增加；只更新活动 Turn | 修订序列与节点计数 |
| ID-05 | 重复流式事件 | 相同内容和状态重复到达 | 无操作；修订和节点数不变 | 事件重放结果 |
| ID-06 | 流式完成 | `streaming` 转 `complete` | 同一消息与 Turn，仅状态更新 | 状态迁移记录 |
| ID-07 | 停止后继续 | `streaming`→`interrupted`→`streaming` | 有强身份时沿用键；否则形成候选且不重复建 Turn | 状态与身份决策记录 |
| ID-08 | 编辑用户问题且 ID 保持 | 正文改变、平台 ID 不变 | 同一消息修订；后续路径标记需重投影 | 来源 ID、修订和影响范围 |
| ID-09 | 编辑导致新来源 ID | 内容相似但 ID 改变 | 新消息身份；旧元数据不自动转移，除非满足高置信一对一规则 | 新旧键与候选结果 |
| ID-10 | 重新生成回答 | 同一问题出现多个回答版本 | 版本分别保留；活动版本切换不覆盖旧身份 | 回答组/版本矩阵 |
| ID-11 | 版本切换 | 页面切换活动回答 | 只更新活动版本标记；不新增消息 | 切换前后集合比较 |
| ID-12 | 前序插入或补载 | 消息逻辑序号整体变化 | 稳定键保持；仅顺序重算 | 键和顺序差异 |
| ID-13 | 部分快照 | 本次未包含历史消息 | 不删除旧投影或元数据 | completeness 与保留结果 |
| ID-14 | 孤立 Assistant | 缺少可确认 Question | 标记 `unresolved`，不强行错配 | 诊断码与零错误边 |
| ID-15 | 同键角色冲突 | 同一消息键出现不同角色 | 熔断自动合并 | 冲突诊断与旧地图保留 |
| ID-16 | 派生键漂移 | 编辑造成序号和指纹变化 | 生成可解释迁移候选；不静默错绑 | 候选证据与置信度 |
| ID-17 | 一对多候选 | 一个旧消息匹配多个新消息 | 停止自动迁移，等待确认 | 候选集合与元数据保留 |
| ID-18 | 元数据重挂接成功 | 高置信一对一身份映射 | 布局/标题/标签重挂接；内容和逻辑边不被布局改写 | 元数据引用及边对比 |
| ID-19 | 低置信新快照 | 只有顺序或内容相似证据 | 不覆盖高置信旧映射，不迁移元数据 | 置信度与熔断记录 |
| ID-20 | 策略版本升级 | 同一来源由新策略生成候选键 | 保留旧键，产生版本化迁移映射；不可就地静默替换 | 策略版本与迁移记录 |
| ID-21 | 会话标题变化 | 仅标题被修改 | 会话键不变 | 标题与键对比 |
| ID-22 | 键碰撞 | 两条不同消息生成同一键 | 阻断合并并报告冲突 | 碰撞诊断与数据未覆盖证据 |
| ID-23 | 日志与序列化检查 | 检查快照、诊断和候选输出 | 无 DOM、令牌、Cookie、完整正文或完整敏感 URL 参数 | 白名单字段审计与敏感模式扫描 |

## 14. T0-02 退出标准

- [ ] `ConversationSnapshot`、`SourceConversation`、`SourceMessage` 的必需字段、空值语义和版本规则均能由 ADP 输出或明确报告不支持。
