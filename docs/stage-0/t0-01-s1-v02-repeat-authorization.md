# T0-01 S1 探针 0.2.0 重复复测授权包

## 1. 决策目的

首次 `0.2.0` S1 回测在 3/3 条 Assistant 消息上识别到 `completed-signal`，且没有流式或冲突信号。该结果只是一份单次、低置信度候选证据，尚不能证明相同页面重复读取时保持一致。

本授权包申请在同一份专用、非敏感、可丢弃的 S1 合成 ChatGPT 会话上再执行两次只读读取，形成 `V02-R02` 与 `V02-R03`。PO 已于 2026-09-07 明确批准；必须继续遵守逐次执行与熔断门禁。

## 2. 申请批准的范围

| 项目 | 限定范围 |
|---|---|
| 决策编号 | `D0-06` |
| 目标页面 | 原 S1 专用、非敏感、可丢弃的合成会话 |
| 探针版本 | `0.2.0`，schema `2` |
| 探针 SHA-256 | `5B4B890B5DC384A14F3652DDADF951576A86C3BB3AE520C2A7D67CB5D966E1DB` |
| 新增运行次数 | 两次，分别登记为 `T0-01-S1-V02-R02`、`T0-01-S1-V02-R03` |
| 页面状态 | 使用与 `V02-R01` 相同的已完成静态页面；不刷新、不制造新消息或状态变化 |
| 数据输出 | 仅转交探针生成的脱敏 schema 2 JSON |
| 授权有效期 | 两次结果取得或任一熔断条件触发后立即失效 |

## 3. 允许动作

1. 人工确认仍位于原 S1 专用测试会话。
2. 人工确认 `AICMReadonlyProbe.version` 为 `0.2.0`。
3. 手动调用一次 `run()` 取得 `V02-R02`，预览后转交完整脱敏 JSON。
4. 等待 TL 确认 R02 已安全接收后，再手动调用一次 `run()` 取得 `V02-R03`，预览后转交完整脱敏 JSON。
5. 完成 R03 或触发熔断后调用 `dispose()` 清理临时全局对象。

两次读取必须是两个独立的人工调用，并分别保留各自的 `capturedAt`。不得复制上一份输出冒充新运行。

## 4. 明确禁止

- 不发送、编辑、停止、重试、重新生成、分支或删除消息。
- 不点击复制、反馈或其他响应控件；探针只观察候选是否存在。
- 不刷新页面、不切换会话、不新建标签页，不主动制造 DOM 生命周期变化。
- 不读取网络、Cookie、令牌、账户信息、浏览历史或其他标签页。
- 不使用网络请求、本地存储、下载或剪贴板能力；仅由操作人查看并人工转交脱敏 JSON。
- 不保存正文、真实来源 ID、属性原值、URL 或 DOM 片段。
- 不运行 S2、S3，不把两次额度转用于其他页面或探针版本。
- 不因某次输出不符合预期而自行追加第三次补测。

## 5. 逐次执行与熔断

### R02

1. 只运行一次并检查输出为 schema `2`、probe `0.2.0`。
2. 发现正文、真实 ID/URL、属性原值、DOM 片段、错误版本、非 S1 页面或异常字段时，不转交结果，立即 `dispose()` 并报告抽象错误。
3. 转交 R02 后停止，等待 TL 确认；不得提前运行 R03。

### R03

1. 只有 TL 明确确认 R02 已接收且未触发熔断后才运行一次。
2. 使用与 R02 相同的检查和熔断规则。
3. 转交后立即 `dispose()`；授权额度用尽。

任何结果即使为 `unconfirmed`、`streaming-signal` 或 `conflicting-signals` 也必须按事实记录，不得通过重复运行挑选“更好”的结果。

## 6. 验收口径

重复性检查只在三份 schema 2 结果之间进行：`V02-R01`、`V02-R02`、`V02-R03`。

1. 三份均为 6 条消息，角色严格交替且序号连续。
2. 三份均有 3 条 Assistant；每条均为 `completed-signal`，只有 `copy-action`，且 `ariaBusyTrue=false`。
3. 每份 summary 均为完成/流式/冲突计数 `3/0/0`。
4. 删除唯一允许变化的 `capturedAt` 后，三份完整 JSON 值树一致。
5. 任一差异都必须登记为差异证据，不得静默归一化；只有用户粘贴中的 HTML 空格实体可转换为普通 JSON 格式空白，数据值不得改变。
6. 每份结果分别通过结构断言、SHA-256、禁止内容扫描和 QSR 人工复核。

全部满足时，只能将结论提升为“相同 S1 静态页面的三次读取重复性通过”。这仍不能证明刷新后的身份稳定性、其他账户/页面版本兼容性、S2 富结构或 S3 动态状态正确性，也不能把候选当成 OpenAI 官方契约。
