# S2：长会话与富结构

## 目标

创建一个 20 Turn 的线性测试会话，覆盖长页面、不同 Markdown 结构和局部定位。主题完全虚构，不使用真实业务数据。

## 虚构主题

规划虚构空间站“晨星港”的公共知识节。所有名称、数字与活动均为合成内容。

## 执行脚本

每次等待上一条回答完成后，再发送下一条。不得临时加入真实信息。

1. **S2-T01**：`为虚构空间站“晨星港”策划一个三天公共知识节，请先用五条要点说明目标。`
2. **S2-T02**：`列出四类虚构参与者，并分别说明他们最关心的问题。`
3. **S2-T03**：`用 Markdown 表格给出三天的上午、下午和晚间主题。`
4. **S2-T04**：`为第一天上午设计三个连续环节，每个环节写名称、时长和产出。`
5. **S2-T05**：`把第一天的三个环节转换成有序列表，并为每项增加一个风险提示。`
6. **S2-T06**：`给出一个虚构报名记录的 JSON 示例，只包含 participantId、track 和 confirmed 三个字段。`
7. **S2-T07**：`写一段 TypeScript 函数示例，用于统计 confirmed 为 true 的虚构报名数量，并放在代码块中。`
8. **S2-T08**：`解释上一段函数的输入、输出和一个边界情况，使用三个小标题。`
9. **S2-T09**：`为知识节设计四种虚构徽章，用两列表格展示名称和获得条件。`
10. **S2-T10**：`写一段约三百字的虚构开幕词，不提及任何真实人物或机构。`
11. **S2-T11**：`把开幕词压缩为三句，每句不超过二十五个汉字。`
12. **S2-T12**：`列出六项物资，每项包含数量、用途和一个替代方案。`
13. **S2-T13**：`为突发停电设计四步应对流程，明确每一步的负责人角色，但不要使用人名。`
14. **S2-T14**：`把应对流程表示为纯文本箭头链，避免使用图片。`
15. **S2-T15**：`提供五个常见问题与简短答案，使用问答列表。`
16. **S2-T16**：`选择其中两个常见问题，分别扩写为约一百字回答。`
17. **S2-T17**：`给出三项活动成功指标，并为每项写计算口径。`
18. **S2-T18**：`用表格比较“参与度”“完成率”“满意度”三个指标的优点与局限。`
19. **S2-T19**：`总结目前方案中的五个关键决定，并按重要性排序。`
20. **S2-T20**：`用不超过一百五十字写最终摘要，并列出下一步三项行动。`

## 富结构覆盖

| 结构 | 主要 Turn |
|---|---|
| 无序列表 | T01、T12、T17、T20 |
| 有序列表 | T05、T13、T19 |
| Markdown 表格 | T03、T09、T18 |
| JSON 代码块 | T06 |
| TypeScript 代码块 | T07 |
| 多级标题 | T08 |
| 长文本 | T10 |
| 短文本与压缩 | T11、T20 |
| 问答结构 | T15、T16 |

## 完成条件

- 页面中存在 20 个用户问题及对应已完成回答。
- 不执行编辑、重试、重新生成或分支。
- 不上传附件，不加入真实链接、姓名、账号或业务材料。
- 如果平台因长度只渲染部分历史，记录为虚拟化/懒加载观察项，不能假定消息已删除。

## 探针期望

- 投影结果为 20 个 Turn/Card，逻辑顺序稳定。
- 能定位第 1、10、20 个 Turn，并记录长距离滚动或懒加载行为。
- 富结构在领域快照中以安全、可序列化形式表达，不保存原始 DOM。
- 页面刷新与重复读取不产生重复 Turn。
- 本脚本不要求回答内容逐字一致，只验证结构类别与消息边界。
