# S1：基础完成线性会话

## 目标

创建一个恰好 3 个用户 Turn 的简单线性会话，验证：

- 用户与 Assistant 角色识别。
- 消息顺序识别。
- 一个 Question 与后续 Answer 聚合为一个 Turn/Card。
- 已完成回答状态识别。
- 刷新后同一消息不重复投影。

## 虚构主题

为虚构社区“蓝湾社区”设计一个周末共享书架活动。内容不对应真实组织、地点或人员。

## 执行脚本

### S1-T1

发送：

> 为虚构的“蓝湾社区”设计一个周末共享书架活动。请用三条简短要点说明活动目标，不要引用真实地点、组织或人物。

预期结构：一个用户问题；一个已完成 Assistant 回答；回答包含三条列表项。

### S1-T2

等待上一条回答完成后发送：

> 把这三个目标整理成一个两列表格，表头为“目标”和“衡量方式”。

预期结构：第二个用户问题；一个已完成 Assistant 回答；回答包含 Markdown 表格。

### S1-T3

等待上一条回答完成后发送：

> 最后给这个虚构活动取一个不超过八个汉字的名称，并用一句话解释名称含义。

预期结构：第三个用户问题；一个已完成 Assistant 回答；回答包含短标题和一句解释。

## 完成条件

- 页面中可以观察到 3 个用户问题和 3 个对应回答。
- 三个回答均已停止流式变化。
- 不执行编辑、重试、重新生成或分支。
- 不添加附件或真实信息。

## 探针期望

- 投影结果恰好为 3 个 Turn/Card。
- 逻辑关系为连续的两条 `sequence` 边。
- 重复读取同一页面三次，来源身份与 Turn 数量保持一致。
- 本脚本不规定实际 CSS 选择器、消息 ID 或回答正文。
