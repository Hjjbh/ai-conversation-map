# ChatGPT Site Adapter 规范

## 1. 目的

Adapter 是对 ChatGPT 网页不稳定性的隔离层。其他核心模块只依赖标准化能力与事件，不接触 CSS 选择器、页面路由或 DOM 细节。

## 2. 必需能力

| 能力 | 首版要求 | 失败行为 |
|---|---:|---|
| 识别受支持页面 | 必须 | 显示“不在受支持会话页” |
| 获取会话引用 | 必须 | 禁止持久化不明来源投影 |
| 读取消息快照 | 必须 | 返回诊断，不写入半可信图 |
| 观察消息变化 | 必须 | 允许手动刷新降级 |
| 定位来源消息 | 必须 | 提供重新扫描按钮 |
| 获取当前活动 Turn | 应支持 | 无法判断时不自动选中 |
| 创建真实分支 | 待验证 | 显示能力不可用，不伪造 |
| 带上下文发起追问 | 待验证 | 仅填充草稿或复制文本，需用户确认 |

## 3. 能力声明

Adapter 每次连接页面时产生能力快照，而不是把能力写死为全局常量。能力至少区分：支持、暂不支持、需要用户确认、验证失败。分支按钮依据当前快照展示。

## 4. 解析策略

### 选择器分层

1. 优先语义属性、稳定数据属性与可访问性信息。
2. 其次使用结构关系和角色特征。
3. 最后才使用易变 class 名。

每个关键目标允许多种策略，并记录命中策略。任何策略升级都通过 fixture 测试验证。

### 快照而非边走边写

Adapter 先构造完整、带置信度的 `ConversationSnapshot`，Projection Engine 校验后再合并。解析过程中不直接修改图谱或数据库。

### MutationObserver 使用约束

- 观察范围限定到会话容器。
- 变化事件进行去抖与合并。
- 不为每个字符触发全量 DOM 扫描。
- 页面导航、会话切换和容器替换时重新绑定 observer。
- 扩展卸载、页面离开或重新绑定前必须释放 observer。

## 5. 页面变化处理

Adapter 需要输出结构化诊断：页面类型、策略版本、消息计数、未识别节点数、定位句柄可用率和最近错误。不得记录完整聊天正文到普通日志。

当解析置信度低于阈值时：

1. 保留上一次有效地图。
2. 标记数据可能过期。
3. 提供重新扫描。
4. 禁止自动覆盖稳定来源映射。
5. 允许导出脱敏诊断，便于修复 Adapter。

## 6. 双向定位句柄

定位句柄应优先保存稳定消息 ID 或可重建定位信息，不保存 DOM 引用。定位时依次尝试：稳定属性、来源序号加内容指纹、局部文本锚点。成功后短暂高亮；失败时返回明确原因。

## 7. 分支策略验证清单

在进入代码实现前，必须用当前 ChatGPT Web 单独完成技术探针，回答：

- 是否存在用户可见且稳定的原生“从此处分支”操作？
- 分支后能否可靠获取新会话 ID 与父消息锚点？
- 是否需要打开新标签页或等待路由变化？
- 是否只能通过编辑旧问题、重试回答或复制上下文近似实现？
- 哪些动作必须保留用户点击，不能由脚本自动触发？

探针结论以新的 ADR 记录。验证前，文档不承诺自动真实分支。

## 8. 合规边界

- 仅在用户打开的 ChatGPT 页面和明确操作范围内工作。
- 不读取认证令牌、不调用未授权私有接口、不绕过平台限制。
- 优先通过可见页面能力完成动作。
- 自动发送消息默认禁止；任何发送动作必须有明确用户确认。
